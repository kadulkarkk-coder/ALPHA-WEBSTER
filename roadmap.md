# WEBSTER V2 Roadmap

## Philosophy

> Build Webster like an operating system, not like an app.

The UI is the final layer. The core architecture comes first.

## Development Rules

1.  Webster must remain runnable after every sprint.
2.  The core never depends on the UI.
3.  Every module has a single responsibility.
4.  Communication happens through interfaces, events, or the service
    container.
5.  Every sprint includes implementation, tests, and documentation.
6.  External integrations are isolated behind adapters.
7.  Build architecture first, features second.
